## Boundaries and honest limitations

- No live Desktop installation, authenticated provider call, paid generation, publishing or release was performed. Chromium uses SDK stubs, not the live Hermes UI components; screenshots demonstrate layout, not native-host visual approval.
- PBR channel roles must be supplied by typed asset metadata. The integrated fixture uses real cached PBR map files in the existing local asset index. It does not invent a provider material-bundle schema or infer map roles from unrelated generic cloud images. HDR/EXR modality is recognized from the asset filename.
- Workspace video uses V05's scoped buffered `/file` fallback. A host tool-media `resolveUrl` can stream Range media, but that capability is not fabricated for a standalone workspace route.
- An in-flight workspace is permanently invalidated on profile/connection change; chrome refreshes in the new scope. Reopening through a command/chip mounts a fresh workspace without resurrecting old selections or uploads.

Eight light/dark screenshots in `screenshots/` were generated by the real Chromium theme/tab test. Fixture UI, filenames, IDs and credits are synthetic.
